
十条硬性约束（S1–S10）对应事故各环节：子智能体任务独占、并发声明封顶 500、禁止"连上就断"、
强制指数退避（base 200ms ×2 cap 30s ±20% 抖动）、客户端熔断（失败率>5% / TIME_WAIT>8000 /
p99>5s / RSS>2GB）、总时长≤15min、异步客户端（禁 thread-per-client）、内存有界、
禁改系统配置、禁留孤儿进程。

配套：开跑前自检清单（ulimit -n / ip_local_port_range / somaxconn / ss -s 基线 / 服务端 PID）、
两段式用例设计（A 容量=长连接+吞吐，B 握手=限速 100 conn/s 单独跑）、分档放行节奏（1 → 50 → 200 → 400）。

**Valgrind 约束写入 `docs/STRESS_TEST_RULES.md` §9**：Valgrind 与压测必须互斥。
核心风险：memcheck 下程序慢 20–50 倍 → 客户端建连超时 → 失败重连正反馈 → **比正常运行更容易触发端口耗尽**
（正是 10-16 假死机制）。正确用法：Valgrind 只做功能验证（单局/单测），压测前确认无 valgrind 在跑；
若必须网络验证则并发降到 1–5、限时 ≤2 分钟、禁止重试。Valgrind 期间 vmmem 涨到 8–12GB 属正常，勿误判泄漏。

## 追加：Valgrind 最新版的结论与 TSan 分工（§9.7–9.9）

用户确认 WSL 内 valgrind 为最新版（≥3.24）。结论：**版本新 ≠ DRD 结果可信**。
新版已解决 C++11+ atomics 的 happens-before 推断、AVX/AVX2 支持、shared_mutex/atomic<T*> 识别；
但**没解决** DRD/Helgrind 对 asio `strand`（逻辑串行化非锁）和**无锁数据结构**的结构性误报——工具模型限制，非 bug。

工具分工建议：memcheck 保留为内存门禁；**竞争检测改用 TSan**（编译器插桩、懂 C++11 内存模型、比 DRD 快 10–20 倍）。
`tools/valgrind_check.sh` 目前是「DRD 先筛 → TSan 确认」，建议**反过来**（TSan 快且准，DRD 只做交叉验证）。

TSan 落地要点（不改 CMakeLists）：`-DCMAKE_CXX_FLAGS="-fsanitize=thread -fno-omit-frame-pointer -g -O1"` 配 build-tsan；
WSL2/内核 6.x 必做 `sudo sysctl vm.mmap_rnd_bits=28`（否则报 unexpected memory mapping）；
`TSAN_OPTIONS="halt_on_error=0 second_deadlock_stack=1"`；TSan 与 valgrind 不可同时用；TSan 构建下禁止压测。

项目三处高风险并发改动建议用 TSan 重点跑：共享只读 TT（无锁）、GameManager 的 ai_thinking_worker 与 io_context 共享棋局状态、训练参数/检查点的原子替换。
